# Logo and icon

`frontend/logo.svg` is the single source of the AI Gauge mark. `frontend/logo.png`, the portable
`aigauge.exe`'s embedded icon, and the MSIX package's Store tiles are all generated from it.

## Regenerating `frontend/logo.png`

```powershell
.\build.ps1 -Task logo
```

After editing `logo.svg`, update `$expectedSourceHash` in `hack/convert-logo.ps1` (its guard
against a stale PNG) with:

```powershell
(Get-FileHash frontend/logo.svg -Algorithm SHA256).Hash.ToLowerInvariant()
```

## Windows executable icon (portable `aigauge.exe`)

`hack/prepare-windows-resources.ps1` embeds the icon and file metadata into `aigauge.exe` via
[go-winres](https://github.com/tc-hib/go-winres) (`go install github.com/tc-hib/go-winres@v0.3.3`).
`build.ps1 -Task build` runs this unless `-SkipWindowsResources` is passed. `release.yml` does not
skip it, since `aigauge.exe` is also uploaded to GitHub Releases as the portable executable.

## MSIX package icons

Separately, `hack/package-msix.ps1` rasterizes `logo.png` straight into the MSIX's Store tile
assets. This doesn't involve go-winres or the executable icon at all.

## How the gauge ring is drawn

The gauge mark is 5 rounded ring wedges arranged around a circle of 7 equal slots (the 2 bottom
slots are intentionally left empty), plus a separate needle path. Every wedge is just the same
shape rotated to a different angle, so drawing (or redrawing) one means picking 5 numbers and
running them through one formula - not hand-placing Bezier points.

**Current numbers**, all relative to center `(512, 512)` on the 1024x1024 canvas:

| parameter | value | meaning |
| --- | --- | --- |
| `outerR` | 420 | outer edge of the ring |
| `innerR` | 210 | inner edge of the ring (255 originally; thickened for a bolder mark) |
| `cornerR` | 26 | how much each of the wedge's 4 corners is rounded |
| slot pitch | `360/7 ≈ 51.4286°` | 7 equal slots around the circle; 2 at the bottom stay empty |
| wedge span | `≈ 42.998°` | angular width of one filled wedge (pitch minus an `8.43°` gap to the next) |
| slot 0 start | `145.643°` | `angleLow` of the first filled wedge; the other 4 are `+ i · pitch` |

**To draw one wedge**, given its two boundary angles `angleLow` and `angleHigh` (`angleHigh =
angleLow + 42.998` for the current design):

1. Compute how far the corner rounding eats into each arc, in degrees, at that arc's own radius:
   `deltaOuter = cornerR / outerR · (180/π)`, `deltaInner = cornerR / innerR · (180/π)`.
2. Define `point(r, deg) = (512 + r·cos(deg·π/180), 512 + r·sin(deg·π/180))` - a point at radius
   `r`, angle `deg`.
3. Emit the path as 4 rounded corners (`Q`) alternating with 2 arcs (`A`, one per radius) and 2
   short radial edges (`L`):

   ```
   M  point(outerR, angleLow + deltaOuter)
   A  outerR outerR 0 0 1  point(outerR, angleHigh - deltaOuter)
   Q  point(outerR, angleHigh)  point(outerR - cornerR, angleHigh)
   L  point(innerR + cornerR, angleHigh)
   Q  point(innerR, angleHigh)  point(innerR, angleHigh - deltaInner)
   A  innerR innerR 0 0 0  point(innerR, angleLow + deltaInner)
   Q  point(innerR, angleLow)  point(innerR + cornerR, angleLow)
   L  point(outerR - cornerR, angleLow)
   Q  point(outerR, angleLow)  <close to the M point>
   ```

4. Repeat for the 5 filled slots (`angleLow = 145.643 + i · 51.4286` for `i = 0..4`), one `<path>`
   per wedge, each with its own `fill="url(#segN)"` gradient.

This formula was reverse-engineered from the original hand-authored path coordinates - it
reproduces them exactly to one decimal place - so it's the reliable way to redraw the wedges at a
different thickness or corner radius, rather than nudging existing Bezier points by hand.

The needle is a separate, unrelated path (`frontend/logo.svg`'s `needle` element: a straight edge
from its tip down to a rounded base, drawn with a thick stroke) and isn't generated by this
formula. If you shrink `innerR` further, check the needle's base extent against it first - at
`innerR` below roughly 195 the needle's base starts touching the ring.
